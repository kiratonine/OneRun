# ТЗ: «Сводный рейс» — консолидация грузов в отдалённые посёлки Мангистау

**Хакатон:** Mangystau Hackathon, кейс «Цифровая платформа грузоперевозок и последнего километра»
**Дедлайн сдачи:** 20.08.2026, 16:00
**Ресурс:** 3 человека × ~12 часов (1 фронтенд, 2 фуллстека на бэкенде)
**Статус документа:** рабочее ТЗ, версия 1

---

## 1. Суть продукта

Мелкие грузоотправители в Мангистауской области поодиночке не набирают машину: магазину в Акшукуре нужно 80 кг, стройке в Шетпе — 200 кг, ФХ в Бейнеу — 150 кг. Ни одна из этих заявок не окупает рейс, поэтому либо не везут, либо везут по цене отдельной машины.

Платформа копит входящие заявки в общий пул. Когда суммарный вес пула переходит порог загрузки, система формирует **один сводный рейс** через все точки назначения, строит маршрут, определяет порядок объезда и порядок погрузки, и делит стоимость рейса между отправителями пропорционально их вкладу.

**Одной строкой:** пять отправителей заказали по чуть-чуть — система собирает из них один рейс, и каждый платит долю вместо полной машины.

## 2. Пользователь и проблема

| | |
|---|---|
| **Кто** | Диспетчер / логист транспортной компании в Актау, обслуживающей область |
| **Вторичный пользователь** | Грузоотправитель — магазин, ферма, стройка в отдалённом посёлке |
| **Проблема** | Мелкая партия не окупает рейс; заявки не сводятся между собой, потому что их негде увидеть вместе |
| **Текущее решение** | Звонки и группы в WhatsApp, сведение «на глаз» или отсутствие сведения вообще |
| **Что даёт продукт** | Автоматическое сведение заявок в рейс + готовый план: порядок объезда, порядок погрузки, стоимость для каждого отправителя |

## 3. Границы MVP

### Обязательно (без этого нет демо)

1. Карта Мангистауской области с реальными населёнными пунктами.
2. Заявка при создании появляется на карте в реальном времени как цветная прямая линия «откуда — куда».
3. Счётчик суммарного веса пула; при переходе порога появляется кнопка «Построить рейс».
4. Формирование рейса: порядок объезда, реальная геометрия маршрута по дорогам, стоимость каждой заявки.
5. Отчёт для перевозчика: маршрут следования, порядок погрузки, стоимость по заявкам, экономический эффект.
6. Вкладка со списком заявок и модальное окно с деталями по клику на линию.
7. Демо-панель: кнопка «Сгенерировать заявки» — заявки падают по одной с интервалом.
8. Задеплоенный фронт + бэкенд + реальная БД.

### Желательно, если останется время

- Форма ручного создания заявки (вкладка «Новая заявка»).
- Выгрузка отчёта в PDF.
- Анимация построения маршрута.
- Экран «эффект для акимата»: сколько километров сэкономлено суммарно.

### Вне объёма — не делаем и не обсуждаем

- Авторизация, роли, регистрация.
- Валидация пользовательского ввода сверх минимальной.
- Безопасность, rate limiting, защита от некорректных данных.
- Мобильная адаптация (демо идёт с ноутбука; телефон нажимает одну кнопку).
- Реальный GPS-трекинг машин.
- Оплата, договоры, документооборот.
- История рейсов, аналитика по периодам.

## 7. Модель данных

```sql
-- Справочник населённых пунктов. Заполняется сидом один раз.
create table settlements (
  id          serial primary key,
  code        text unique not null,      -- 'AKTAU', 'SHETPE', 'BEINEU'
  name_ru     text not null,
  name_kz     text,
  district    text,
  lat         double precision not null,
  lon         double precision not null
);

-- Заявка грузоотправителя.
create table orders (
  id              uuid primary key default gen_random_uuid(),
  code            text unique not null,       -- 'ORD-001'
  from_id         int references settlements(id) not null,
  to_id           int references settlements(id) not null,
  shipper_name    text not null,
  cargo_name      text not null,              -- 'Стройматериалы', 'Продукты питания'
  weight_kg       numeric not null,
  boxes_count     int,
  box_note        text,                       -- '5 коробок по 20 кг, 60×40×40'
  color           text not null,              -- цвет линии на карте
  status          text not null default 'new',-- new | pooled | routed
  created_at      timestamptz default now()
);

-- Сформированный сводный рейс.
create table trips (
  id                 uuid primary key default gen_random_uuid(),
  code               text unique not null,    -- 'TRIP-001'
  status             text not null default 'planned',
  stop_order         jsonb not null,          -- ['AKTAU','AKSHUKUR','SHETPE','BEINEU','AKTAU']
  route_geometry     jsonb not null,          -- GeoJSON LineString от ORS
  total_distance_km  numeric not null,
  total_weight_kg    numeric not null,
  solo_distance_km   numeric not null,        -- сумма отдельных рейсов, для сравнения
  saved_distance_km  numeric not null,
  saved_cost_kzt     numeric not null,
  created_at         timestamptz default now()
);

-- Связка заявка—рейс с рассчитанной долей.
create table trip_orders (
  trip_id        uuid references trips(id) on delete cascade,
  order_id       uuid references orders(id) on delete cascade,
  price_kzt      numeric not null,
  load_position  int not null,                -- 1 = грузить последним, ближе к выходу
  drop_index     int not null,                -- порядковый номер выгрузки
  primary key (trip_id, order_id)
);

-- Отчёт от LLM.
create table reports (
  id           uuid primary key default gen_random_uuid(),
  trip_id      uuid references trips(id) on delete cascade,
  content_md   text not null,
  raw_response jsonb,
  created_at   timestamptz default now()
);
```

### Сид справочника

Минимум 10 населённых пунктов с реальными координатами. Обязательно: **Актау** (хаб), **Акшукур**, **Шетпе**, **Бейнеу**, **Жанаозен**, **Курык**, **Жетыбай**, **Мунайшы**, **Сенек**, **Устюрт**, **Форт-Шевченко**.

Координаты берутся из Nominatim (`https://nominatim.openstreetmap.org/search?q=<название>,+Mangystau&format=json`) или с геопортала `map.e-mangistau.kz`. **Не выдумывать координаты руками** — на питче отдельным пунктом требуется показать, какие реальные населённые пункты использованы.

## 9. API-контракт

Все ответы — JSON. Ошибки не обрабатываются подробно: достаточно 500 с текстом.

### `GET /api/settlements`
Справочник для карты и форм.
```json
[{ "id": 1, "code": "AKTAU", "nameRu": "Актау", "lat": 43.65, "lon": 51.16 }]
```

### `GET /api/orders`
Все заявки текущего пула.
```json
[{
  "id": "...", "code": "ORD-001",
  "from": { "code": "AKTAU", "nameRu": "Актау", "lat": 43.65, "lon": 51.16 },
  "to":   { "code": "SHETPE", "nameRu": "Шетпе", "lat": 44.17, "lon": 52.12 },
  "shipperName": "ИП Әулет", "cargoName": "Стройматериалы",
  "weightKg": 200, "boxesCount": 10, "boxNote": "10 мешков по 20 кг",
  "color": "#ef4444", "status": "new"
}]
```

### `GET /api/pool`
Состояние пула — для счётчика и кнопки.
```json
{ "totalWeightKg": 520, "ordersCount": 6, "thresholdKg": 500, "isReady": true }
```

### `POST /api/orders`
Ручное создание заявки. Тело: `fromCode`, `toCode`, `shipperName`, `cargoName`, `weightKg`, `boxesCount`, `boxNote`.

### `POST /api/demo/seed`
Создать одну следующую заявку из заранее подготовленного набора. Фронтенд дёргает эту ручку по таймеру `DEMO_ORDER_INTERVAL_MS`. Возвращает созданную заявку.

### `POST /api/demo/reset`
Чистит `orders`, `trips`, `trip_orders`, `reports`. Нужна, чтобы прогнать демо повторно.

### `POST /api/trips`
**Главная ручка.** Берёт все заявки со статусом `new`, формирует рейс. Возвращает полный объект рейса:
```json
{
  "id": "...", "code": "TRIP-001",
  "stopOrder": ["AKTAU", "AKSHUKUR", "SHETPE", "BEINEU", "AKTAU"],
  "routeGeometry": { "type": "LineString", "coordinates": [[51.16,43.65], ...] },
  "totalDistanceKm": 812,
  "soloDistanceKm": 1940,
  "savedDistanceKm": 1128,
  "savedCostKzt": 201348,
  "orders": [
    { "orderCode": "ORD-003", "dropIndex": 1, "loadPosition": 1, "priceKzt": 18400 }
  ],
  "report": "## План рейса TRIP-001\n..."
}
```

### `GET /api/trips/:id`
То же самое, для перезагрузки страницы.

## 10. Функциональные требования

### Карта

**FR-01.** При загрузке страницы карта центрируется на Мангистауской области, отображаются маркеры всех населённых пунктов из справочника.

**FR-02.** Каждая заявка рисуется **прямой линией** (не маршрутом по дорогам) от точки отправления к точке назначения. Цвет берётся из `ORDER_LINE_COLORS` по индексу заявки — линии должны визуально различаться.

**FR-03.** Новая заявка появляется на карте без перезагрузки страницы. Механизм: подписка на Supabase Realtime по таблице `orders`, при событии `INSERT` — инвалидация `orders`-запроса TanStack Query.

**FR-04.** Клик по линии заявки открывает модальное окно: код заявки, отправитель, откуда — куда, наименование груза, вес, количество мест, примечание по габаритам. После формирования рейса в модалке дополнительно показывается стоимость и очередь выгрузки.

**FR-05.** После формирования рейса на карте поверх прямых линий рисуется **реальная геометрия маршрута по дорогам** (`ROUTE_LINE_COLOR`, `ROUTE_LINE_WIDTH`), точки объезда нумеруются в порядке следования.

### Пул и триггер

**FR-06.** На экране постоянно виден счётчик: `<суммарный вес> / <POOL_WEIGHT_THRESHOLD_KG> кг` и число заявок.

**FR-07.** Пока суммарный вес меньше порога — кнопка «Построить рейс» отсутствует или неактивна. При достижении порога кнопка появляется. Переход должен быть замечен визуально: это ключевой момент демо.

### Формирование рейса

**FR-08.** По нажатию «Построить рейс» бэкенд:
1. Набирает все заявки со статусом `new`.
2. Определяет порядок объезда точек назначения, начиная и заканчивая в `HUB_SETTLEMENT_CODE`.
3. Запрашивает у ORS Directions геометрию и километраж маршрута по полученному порядку.
4. Считает километраж «если бы каждый ехал отдельно» — сумма радиальных рейсов из хаба туда-обратно.
5. Считает стоимость по каждой заявке (раздел 11).
6. Отправляет сводку в Gemini и получает текст отчёта с планом погрузки (раздел 12).
7. Сохраняет `trips`, `trip_orders`, `reports`; переводит заявки в статус `routed`.
8. Возвращает всё одним объектом.

**FR-09.** Порядок погрузки строится по правилу LIFO: груз, который выгружается **первым**, грузится **последним** и стоит ближе к выходу. Формально: `loadPosition = dropIndex`, где `dropIndex = 1` у первой точки выгрузки, и в отчёте это означает «грузить последним, ставить у дверей».

**FR-10.** Результат построения кэшируется в БД. Повторный `GET /api/trips/:id` не пересчитывает маршрут и не ходит в ORS и Gemini заново — на демо маршрут обязан быть идентичным при каждом показе.

### Отчёт

**FR-11.** После формирования рейса появляется кнопка «Показать отчёт», открывающая отчёт на отдельной вкладке приложения. Формат — отрендеренный Markdown с читаемой типографикой. PDF — только если останется время (печать страницы через `window.print()` с print-стилями, а не генерация PDF на бэкенде).

**FR-12.** Отчёт содержит: маршрут следования по точкам, таблицу «порядок погрузки», таблицу стоимости по заявкам, блок экономического эффекта.

### Список заявок

**FR-13.** Вкладка «Заявки» — таблица всех заявок пула: код, откуда, куда, груз, вес, места, статус, цветовой маркер, совпадающий с линией на карте. После формирования рейса добавляются колонки «очередь выгрузки» и «стоимость».

### Демо-панель

**FR-14.** Кнопка «Сгенерировать заявки» запускает создание `DEMO_ORDERS_COUNT` заявок по одной с интервалом `DEMO_ORDER_INTERVAL_MS`. Набор заявок фиксирован и лежит в сиде — суммарный вес заранее рассчитан так, чтобы перешагнуть порог **на последней заявке**.

**FR-15.** Кнопка «Сброс» очищает пул и возвращает приложение в начальное состояние. Проверяется до питча: демо должно прогоняться подряд минимум трижды без ручного вмешательства в БД.

**FR-16.** Демо-панель доступна с телефона по прямой ссылке — один экран, две крупные кнопки, ничего лишнего.

## 11. Расчёт стоимости и экономического эффекта

### Себестоимость километра

```
COST_PER_KM_KZT = (25 / 100) × 340 × 2.1 ≈ 178,5 тенге/км
```

Источник цены дизеля — розничные котировки АЗС Казахстана, август 2026 (~340 тг/л). Коэффициент 2.1 переводит топливные затраты в полную себестоимость километра (амортизация, зарплата водителя, шины). Оба числа на слайде подписываются как допущения.

### Стоимость для отправителя

Стоимость сводного рейса делится пропорционально **тонно-километрам** каждой заявки:

```
tkm_i     = weight_kg_i / 1000 × distance_hub_to_dest_i
share_i   = tkm_i / Σ tkm
price_i   = total_distance_km × COST_PER_KM_KZT × share_i
```

Так отправитель тяжёлого груза в дальний посёлок платит больше, чем отправитель лёгкого в ближний — это защищаемо на вопросе жюри «а почему такая цена».

### Экономический эффект

```
solo_distance_km  = Σ (distance_hub_to_dest_i × 2)      // каждый едет отдельно, туда-обратно
saved_distance_km = solo_distance_km − total_distance_km
saved_cost_kzt    = saved_distance_km × COST_PER_KM_KZT
```

На экране и в отчёте показывается тремя числами: **было / стало / сэкономлено**, в километрах и в тенге. Это прямой ответ на требование 06 из ТЗ хакатона.

## 12. Работа с LLM

### Что уходит в Gemini

JSON со сводкой рейса: список заявок (пункт назначения, груз, вес, места, габариты), рассчитанный порядок объезда, километраж, рассчитанные цены.

### Что должно вернуться

Markdown-отчёт для водителя и логиста, содержащий:

1. **Маршрут следования** — по пунктам, с километражом между точками.
2. **План погрузки** — таблица «что грузить в какой очерёдности и где размещать в прицепе», построенная по правилу LIFO. Для каждой позиции — обоснование в одну строку.
3. **Стоимость по заявкам** — таблица с переданными ценами.
4. **Особые замечания** — совместимость грузов (продукты и стройматериалы вместе, хрупкое сверху), если из описания заявок это следует.

### Требования к промпту

- Системная инструкция: отвечать **только** Markdown, без преамбулы и без блока ```` ```markdown ````.
- Числа (цены, километры, порядок объезда) модель **не пересчитывает** — они переданы во входных данных и должны попасть в отчёт как есть. Пересчёт цифр моделью — источник расхождений между картой и отчётом.
- Модель отвечает за формулировки, план размещения груза в прицепе и замечания по совместимости.
- Ответ парсится безопасно: `try/catch`, при неудаче показывается заранее заготовленный fallback-отчёт из шаблона на бэкенде. Демо не должно падать из-за чужого API.

## 15. Риски и открытые решения

### Р-01. ORS может не построить маршрут до мелких посёлков
До Устюрта, Сайотеса, Карамсуа дорог в OpenStreetMap может не быть. **Проверить в первый час, до написания логики.** Запасной вариант: расстояние по прямой × коэффициент извилистости 1.3, геометрия — прямая линия. В отчёте такие плечи помечаются как расчётные.

### Р-02. Профиль `driving-hgv` может не пройти по грунтовкам
Если грузовой профиль не строит маршрут — переключиться на `driving-car` и указать это в README.

### Р-03. Квота Gemini или ORS исчерпается на отладке
Кэшировать ответы с первого успешного вызова (FR-10). На демо запросы не уходят вообще — берутся из БД.

### Р-04. «AI для галочки»
В ТЗ хакатона прямо указано, что декоративная интеграция снижает оценку. Опасное место — **если LLM определяет порядок объезда точек**. Языковая модель не решает задачу коммивояжёра надёжно, результат нестабилен от запуска к запуску, и вопрос жюри «а как вы считаете оптимальный маршрут» останется без ответа.

**Решение к принятию до старта разработки** (одно из двух):
- **A.** Порядок объезда считает бэкенд детерминированно — nearest-neighbour от хаба, при 6 точках этого достаточно и считается за миллисекунды. LLM отвечает за план погрузки, замечания по совместимости грузов и текст отчёта. Это защищаемо: «маршрут — алгоритм, размещение груза — модель».
- **B.** Порядок объезда считает ORS `/optimization` (VROOM) с учётом грузоподъёмности. Точнее, но добавляет зависимость и лимит квоты.

В любом варианте LLM не пересчитывает переданные ей числа.

### Р-05. Замоканный маршрут может быть прочитан как заглушка
В ТЗ хакатона отдельно запрещены `localStorage`-заглушки. Кэш результата в Postgres после реального вызова ORS — это кэш, а не мок, и защищается спокойно. Захардкоженный в коде массив координат — мок, и на вопрос «а если добавить седьмую заявку» ответить будет нечем. Разница в одну строку кода и в весь вопрос-ответ на питче.

### Р-06. Синтетические заявки
Реальных отправителей за 12 часов не появится. Не маскировать: на питче указать прямо, что спрос смоделирован, а посёлки, расстояния и цена топлива — реальные.
